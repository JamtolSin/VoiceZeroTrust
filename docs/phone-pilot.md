# Android 실제 기기 통화 실험

이 단계의 목표는 설치한 Android 앱에서 **실제 양방향 음성 통화 → 처음 10초 자동 분석 → 통화 유지 → 버튼 이후 10초 재분석**을 확인하는 것입니다. 기존 휴대전화 번호로 걸려오는 일반 셀룰러 전화 수신은 아직 구현되지 않았습니다. 휴대폰과 PC(또는 다른 Android 기기)가 같은 방에 참가하는 LAN 음성 통화입니다. 이 성공이 셀룰러 연동 성공을 의미하지 않습니다.

## 준비

- Android 8.0 이상 휴대폰, 마이크 권한. iPhone 설치 파일은 제공하지 않습니다.
- 같은 신뢰할 수 있는 Wi-Fi/LAN에 연결된 PC. PC는 유선 LAN이어도 됩니다.
- PC 마이크·스피커 또는 이어폰. 두 Android 기기로도 가능합니다.
- PC Python 3.10~3.13, 첫 모델 다운로드용 인터넷 및 충분한 디스크·메모리.
- APK는 **Phone pilot APK** Actions 실행의 **VoiceZeroTrust-Android-APK** artifact에서 ZIP을 내려받아 압축을 풉니다. GitHub 로그인이 필요하며 보존 기간은 30일입니다. 만료되면 workflow_dispatch로 다시 빌드합니다.

## 설치 및 서버 실행

1. ZIP의 `VoiceZeroTrust-pilot.apk`를 휴대폰으로 옮겨 실행하고 해당 파일 앱의 '알 수 없는 앱 설치'를 허용합니다. 앱은 `VoiceZeroTrust 실험`으로 표시됩니다. 디버그 서명이므로 스토어 배포용이 아닙니다. 다른 빌드의 서명이 달라 업데이트가 거부되면 기존 실험 앱을 지우고 설치하세요.
2. PC에서 이 PR 브랜치를 체크아웃한 저장소 루트에서 실행합니다.

```powershell
python -m venv .venv-phone
.\.venv-phone\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv-phone\Scripts\python.exe scripts/start_phone_pilot.py
```

3. PC 터미널에 표시된 서버 주소 후보 중 휴대폰과 같은 네트워크 주소, `Connection key`, 방 이름을 앱에 입력합니다. 연결 키는 실행마다 새로 생성되며 앱은 키를 저장하지 않습니다. 서버 터미널을 열어둡니다.
4. PC 브라우저에서 `http://localhost:8765`를 열고 같은 키·방 이름을 입력합니다. `통화 참여`를 누르고 마이크를 허용합니다.
5. 휴대폰에서 `실험 통화 연결`을 누르고 마이크를 허용합니다. 화면 밖에서도 통화를 유지하려면 알림을 허용하는 것이 좋습니다.

PC 방화벽이 Python의 사설 네트워크 연결을 막으면 사용자에게 표시되는 방화벽 허용 창에서 사설 네트워크만 허용하세요. 공용 인터넷 포트 개방은 필요하지 않습니다. 휴대폰 브라우저에서 `http://PC주소:8765/health`가 열리는지 먼저 확인하면 연결 문제를 분리할 수 있습니다. 게스트 Wi-Fi의 기기 격리 기능은 통신을 막을 수 있습니다.

기본 모델은 기존 `baseline`이고 첫 요청에서 다운로드합니다. ASR은 기존 Whisper small을 사용합니다. 최초 분석은 몇 분 이상 걸릴 수 있습니다. 서버가 바쁘면 음성을 대기열에 보관하지 않고 사용 불가를 반환합니다. PC 테스트 화면은 자동 분석을 요청하지 않으므로 휴대폰의 분석과 경쟁하지 않습니다. 두 휴대폰에서는 한쪽의 분석이 서버 사용 중으로 표시될 수 있으며 완료 후 수동 재시도합니다.

기존 작은 영어 연구 후보로 연결 경로만 먼저 확인하려면 실행 전에 명시적으로 선택할 수 있습니다. 기본값을 대체하지 않으며 한국어 통화 검증용 모델 성능을 보장하지 않습니다.

```powershell
$env:VZT_PROFILE = 'candidate'
$env:VZT_ASR = '0'  # 전사 없는 음향 채널만 시험할 때
.\.venv-phone\Scripts\python.exe scripts/start_phone_pilot.py
```

## 실제 기기 확인표 — 사람이 수행할 단계

아래 항목은 APK 빌드·서버 자동 테스트와 별개입니다. 사람이 확인하기 전에는 통과로 기록하지 않습니다.

| 항목 | 방법 | 통과 조건 |
|---|---|---|
| 설치 | APK 열기 | 앱 실행, 강제 종료 없음 |
| 음성 통화 | PC와 휴대폰에서 서로 다른 문장 말하기 | 양방향으로 상대방 목소리가 들림 |
| 자동 구간 | 연결 직후 PC에서 약 10초 말하기 | 10초 후 수집 종료, 수신 길이와 실제 분석 결과 표시 |
| 수동 구간 | 자동 분석 완료 후 20초 기다리고 `지금부터 10초 판별` | 이후 구간만 수집, 자동 구간과 다른 분석 ID |
| 전사 구분 | 대기 중에는 '사과', 버튼 이후에는 '바나나' 말하기 | 이후 음성만 분석에 사용됨. ASR 누락은 별도 기록 |
| 짧은 음성·무음 | 수집 중 말하지 않기 | 안전 판정 없음. 판단 보류 또는 모델의 한계가 명시됨 |
| 종료 | 한쪽에서 종료 또는 알림의 종료 | 다른 쪽도 종료, 마이크 표시 사라짐 |
| 화면 이동 | 통화 중 홈으로 이동한 뒤 앱 복귀 | 통화 유지, 결과 확인 가능 |
| 네트워크 단절 | Wi-Fi 끄기 | 연결 실패/종료 표시, 재연결 가능 |
| 권한 거절 | 마이크 거절 후 연결 | 권한 필요, 녹음 시작 안 함 |
| 일반 전화 | 앱의 일반 전화 접근 가능 여부 | 통화 캡처 권한 없음이 표시됨. 이 자체는 음성 캡처 실험이 아님 |

앱의 `테스트 결과 공유`로 기종·Android 버전·분석 결과를 복사/공유할 수 있습니다. 음성은 포함하지 않지만 전사 텍스트가 포함될 수 있으므로 내용을 확인한 뒤 전송하세요.

## 구조 및 데이터 수명

```text
apps/mobile/             Android 네이티브 APK (Java / AudioRecord / AudioTrack)
backend/                 인증·2인 방·PCM 중계·10초 구간 제어·탐지 API
src/detection/           기존 모델·전사·대화 규칙 재사용 (이동/재학습 없음)
infra/docker/            선택적 Docker 실행
tests/test_phone_pilot.py 구간·연결·실패·종료 검증
```

통화는 16kHz/mono/PCM16 음성을 WebSocket으로 중계하는 실험 프로토콜입니다. SIP/WebRTC/PSTN이나 코덱·지터 최적화·수신 푸시는 이번 단계에 포함하지 않습니다. 일반 전화가 들어와 오디오 포커스를 잃으면 실험 통화를 종료합니다. 오디오는 기본 스피커를 사용하며 Bluetooth 경로는 검증하지 않았습니다.

서버는 통화를 중계하는 동안 모든 오디오 프레임을 전달해야 하지만, **탐지용 누적은 지정된 구간에서만** 수행합니다. 자동 시작은 두 참여자의 오디오 준비가 완료된 시점이며 수동 시작은 서버가 명령을 받은 시점입니다. 최대 10초의 벽시계 시간과 320,000바이트 제한을 함께 적용합니다. 네트워크 지연으로 실제 수신 길이는 10초보다 짧을 수 있습니다. 과거 구간 순환 버퍼는 없습니다. 통화 종료 시 미완료 구간은 폐기하고, 이미 시작한 추론은 CPU 스레드가 끝나며 임시 WAV를 정리합니다. Python 메모리의 보안 덮어쓰기를 보장하지 않습니다.

기존 모델은 두 채널을 분리합니다. 합성 클래스 점수는 보이스피싱 확률이 아니며, 내용 분석은 전사에 적용하는 규칙입니다. 첫 10초 인사만으로 사기를 판정할 수 없습니다. 오류·미검출·무음은 안전 판정이 아닙니다.

HTTP/WS는 사설 IPv4/Tailscale 주소만 앱에서 허용합니다. 연결 키는 초기 WebSocket 프레임으로 전달하여 URL 로그 노출을 피하지만, LAN HTTP 자체는 암호화되지 않습니다. 실험용 음성만 사용하세요. 외부 호스팅 전에는 TLS/WSS, 통화 인증/초대, 레이트 제한, 동시 추론 작업 관리가 필요합니다. 서버는 메모리 방 구조이므로 단일 worker로 실행합니다.

## Docker (선택)

```powershell
$env:VZT_TOKEN = '여기에-임의의-긴-영문숫자-연결키'
docker compose up --build
```

Kubernetes는 실제 기기 실험 이후 사람이 직접 진행할 학습 단계로 남깁니다.

## 자동 검증

```powershell
python -m pytest tests/test_phone_pilot.py -q
gradle -p apps/mobile testDebugUnitTest lintDebug assembleDebug
```

Android 빌드: JDK 17, Gradle 8.13, Android SDK 35, AGP 8.13.2. GitHub Actions에서 동일 빌드 후 APK와 SHA256을 제공합니다. transport 테스트는 모델 대역을 사용하며 실제 모델 검증으로 계산하지 않습니다.

참고: [Android 통화 음성 공유 제한](https://developer.android.com/media/platform/sharing-audio-input), [마이크 foreground service 요구사항](https://developer.android.com/about/versions/14/changes/fgs-types-required).
