# 탐지 MVP 실행

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,detection]"
.\.venv\Scripts\python.exe detection_app.py
```

http://127.0.0.1:7861 에서 파일을 넣고 분석한다. Whisper 전사와 음향 탐지 모델은 최초 사용 시
다운로드하며 로컬에서 추론한다. 입력 대사를 직접 적으면 ASR을 대신하며, 녹음과 대사 일치 여부를
보증하지 않는다. 전사·음향 엔진은 별도로 끌 수 있다. 실패한 채널은 판정 불가로 처리한다.

결과는 음향, 전사, 대화 내용, 권장 행동으로 구분된다. 대화 내용은 규칙 기반이며 훈련된 보이스피싱
분류기가 아니다. 교육·인용 문장 처리는 제한적인 완화이며 모든 맥락을 이해하는 것은 아니다.
음향 분류기의 fake score는 해당 모델 클래스 점수이며 사기 확률이 아니다. 모델 카드의 데이터셋
성능을 한국어 실제 통화 성능으로 사용하지 않는다.

CPU 추론이 기본이므로 기존 GPU 합성 앱과 동시에 켤 수 있으나 최초 실행은 느릴 수 있다.
입력/결과를 외부 분석 서버로 전송하지 않는다. 입력 캐시는 .runtime/detection 아래에 저장되고
UI 캐시 정리는 15분 만료 / 60초 간격이다. OneDrive 폴더에서는 로컬 캐시도 동기화될 수 있다.

추가 설계 및 모델 근거는 detection-backend.md, 전체 PR 배치는 defense-plan.md를 참고한다.

## 로컬 실행 확인 (2026-09-12)

공식 예제 참조를 사용해 앞서 만든 Qwen 한국어 교육 합성 파일(9.28초)에서 음향 탐지와
한국어 자동 전사를 실행했다. 음향 모델은 합성 클래스 점수 약 0.1114를 반환했다.
이는 알려진 합성 샘플에도 낮은 점수를 줄 수 있음을 보여 주며, 해당 모델로 한국어 Qwen
합성 음성을 신뢰성 있게 분류한다고 주장할 수 없다. 결과 UI는 임계값 판정 없이 원시 클래스
점수와 한계를 표시한다. 이 단일 샘플 확인은 정확도·오경보율 평가가 아니다.
